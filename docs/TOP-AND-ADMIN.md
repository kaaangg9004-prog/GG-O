# 자유 광장, 카테고리, TOP 글, 통합 관리

## 커뮤니티

게시판은 `자유 / 밈 / 연예인 / 취미 / 패션 / 음악`입니다. 자유는 모두가 모이는 광장이고, 전체 탭은 모든 카테고리를 모읍니다. 예전 뷰티 글은 패션으로, 케이팝은 음악으로, 정보는 자유로 이전하며 본문·댓글·익명 번호를 유지합니다.

인기 게시판 이름은 **TOP 글**입니다. 게시글의 추천/좋아요 버튼을 제거했으며 기존 기기 데이터의 likes 값이나 이벤트의 별도 반응은 TOP 계산에 사용하지 않습니다. 이벤트 좋아요/싫어요와 취향 투표는 기존 기능으로 유지합니다.

## 실시간 점수와 순위

기본 공식:

```text
score = (views + visibleComments × 15) × 0.5 ^ (ageHours / 24)
```

- 최소 선정 점수: 50점
- 댓글 가중치: 15
- 시간 가중치 반감기: 24시간
- 후보 기간: 최근 7일
- 점수 내림차순, 같은 점수는 최신 작성순/ID순
- 커뮤니티 TOP은 상위 30개, 홈 미리보기는 상위 5개
- 선정 여부는 반올림 전 점수로 판단하고, 화면은 소수점 한 자리로 표시

시계가 자정을 지나도 누적 조회수·댓글수·순위를 초기화하지 않습니다. 점수는 작성 후 경과시간에 따라 연속해서 낮아집니다. 새 글에 조회/댓글이 쌓이면 앞서고, 오래된 글은 자연스럽게 내려갑니다. 숨김·삭제된 글과 숨김·삭제된 댓글은 선정 및 점수 계산에서 제외합니다. 원래 게시글을 조회하는 목록이므로 글을 복제하거나 댓글/익명 번호를 새로 만들지 않습니다.

운영자는 사이트 설정에서 최소 점수, 댓글 가중치, 반감기, 후보 기간을 바꿀 수 있습니다. 임의 추천 버튼이나 일반 사용자가 쓰는 점수 입력 API는 없습니다.

## 자동 반영

- 로컬 체험: 로그인한 회원이 글을 열면 해당 브라우저의 중복 조회를 24시간 동안 제외하고 조회수를 저장합니다. 댓글 변경은 즉시 같은 상태에 반영됩니다. 15초마다 시계를 갱신해 시간에 따른 순위/선정 여부도 다시 계산합니다.
- 서버 모드: 로그인한 회원이 글을 읽으면 신뢰하는 Worker의 `/view`로 콘텐츠 ID만 보냅니다. 댓글 작성/수정/삭제 후에는 안전한 feed RPC를 즉시 다시 읽습니다.
- 다른 이용자의 활동과 시간 경과는 `anonymous_feed`를 15초마다 다시 읽어 반영합니다. 숨겨진 탭은 폴링을 멈추고 돌아오면 즉시 갱신합니다.
- 이전에 시작한 느린 응답이 최신 결과를 덮어쓰지 않도록 요청 순서를 확인합니다. 갱신 때문에 열린 게시글/댓글 초안을 초기화하지 않습니다.
- 원본 posts/comments의 Realtime 구독은 사용하지 않습니다. 사용자 ID/IP를 제거한 기존 RPC 보안 경계를 유지합니다.

## 서버 조회수 보호

`backend/anonymous-api/src/index.ts`의 `POST /view`는 조회 집계 전용이며 본문이나 댓글을 반환하지 않습니다. 상세 읽기는 로그인한 회원만 가능하며, 클라이언트는 회원 인증 후 이 엔드포인트를 호출합니다. Cloudflare 런타임이 설정한 접속 IP만 받아 `게시글 ID + UTC 날짜 + IP`를 별도 서버 비밀 키 `VIEW_HASH_SECRET`으로 HMAC 처리합니다. 원본 IP나 해시를 브라우저 응답에 반환하지 않습니다. 같은 접속 IP의 같은 글은 UTC 날짜별 한 번만 집계합니다. 공유 네트워크에서는 여러 방문자가 같은 IP로 합산될 수 있으므로 이 값이 고유한 사람 수를 뜻하지는 않습니다.

DB의 `anonymous_trusted_view`는 service_role만 실행할 수 있습니다. 일반 브라우저가 view_count, 회원 ID, IP, viewer_hash를 지정해 집계할 수 없습니다. 중복 방지 정보는 비공개 스키마에 두고 조회 요청 시 오래된 날짜 기록을 정리합니다. 누적 view_count 자체는 날짜별로 초기화하지 않습니다. 실제 출시 전 중복 방지 정보의 정기 정리 및 보유 정책도 확정합니다.

Worker의 서버 비밀 설정에 32자 이상의 무작위 `VIEW_HASH_SECRET`을 추가해야 합니다. 기존 쓰기 API 설정과 함께 배포하며, 키를 `NEXT_PUBLIC_` 환경변수나 Git에 넣지 않습니다. 이 설정이 없거나 조회 집계 요청이 실패해도 본문 열람은 유지합니다. 임의의 X-Forwarded-For 헤더는 사용하지 않습니다.

## 통합 관리 페이지

주소는 `/#admin`입니다. 로그인한 BBBB/0000만 체험할 수 있고 AAAA/0000에는 관리 메뉴가 표시되지 않습니다. 실제 계정은 DB 관리자 역할을 검사합니다. 화면 접근 여부와 별개로 모든 관리 RPC에서 권한을 다시 확인합니다.

관리 메뉴:

1. 운영 현황: 게시글, TOP 글, 신고, 회원 현황 및 주요 작업 바로가기
2. 게시글·댓글: 분류 이동, 숨김, 복원, 확인 후 삭제, 댓글 숨김/복원
3. 신고 처리: 기존 신고 검토/조치 및 실제 서버의 신고 작성자 확인·제재
4. 투표 관리: 기존 투표 등록·편집·삭제·상세 편집
5. 이벤트 관리: 기존 이벤트 등록·편집·삭제
6. 매거진 관리: 제목·분류·소개·표지·본문 등록·편집·삭제
7. 고객지원: 전체 문의, 비밀번호 없는 운영자 열람, 답변
8. 긴급 요청함: 기존 비공개 요청함/현재 탭의 안전한 체험 요청함
9. 회원 관리: 7일 정지, 영구 차단, 이용 제한 해제, 관리자 계정 보호
10. 사이트 설정: TOP 점수 설정, 언어별 사이트 공지, 게시글/익명댓글 작성 허용

삭제는 일반 공개 목록에서 제외하는 소프트 삭제이며 운영자가 복원할 수 있습니다. 관리자 조회/변경은 서버 감사 로그에 기록합니다. 실제 관리자 역할의 부여는 브라우저의 닉네임이나 버튼으로 하지 않습니다.

체험 모드의 설정/게시글/매거진/회원 제한은 기존 로컬 저장 구조에 보관합니다. 긴급 요청은 이전처럼 메모리에만 남고 새로고침·로그아웃 때 삭제됩니다. 실제 계정의 서버 오류를 로컬 저장으로 우회하지 않습니다.

## 연결과 검증 범위

- 기존 Supabase migration 001–008 다음에 `202611160009_square_hot_admin.sql`을 적용합니다. 009는 기존 카테고리, private settings, TOP score/feed, trusted view, 관리자 관리/회원/매거진 RPC를 포함합니다.
- 설정 값: 기존 Supabase URL/공개 키, 배포한 쓰기 Worker 공개 URL, Worker의 서버 service_role 키, 정확한 Origin 허용 목록, 별도 VIEW_HASH_SECRET.
- 실제 Supabase 프로젝트 및 Worker 연결이 아직 없어 공개 사이트에서는 기기별 체험 데이터로 동작합니다. 여러 방문자·기기 사이의 공유 집계/운영은 이 연결 후 활성화해야 합니다. 기존 이벤트 기능의 서버 연동 상태 등도 출시 전 별도 확인합니다.
- DB 검증은 PGlite PostgreSQL 엔진의 auth/storage 모형에서 실행합니다. 실제 Supabase의 OAuth·PostgREST·배포 헤더·여러 실계정 부하 검증을 대체하지 않습니다.
- 브라우저 자동화 도구가 제공되지 않아 실제 모바일/PC 화면 QA는 수행하지 않았습니다. DOM 동작·언어·빌드·배포 자산을 확인합니다.

관련 파일은 `src/lib/community.ts`, `src/components/top-posts.tsx`, `src/components/community-navigation.tsx`, `src/components/admin-console.tsx`, `src/lib/site-admin.ts`, `src/components/magazine-manager.tsx`입니다.

- 열람 권한 변경은 009 다음에 `202611160010_member_read_access.sql`을 적용합니다. TOP 목록·점수는 공개지만 본문·댓글·투표 상세는 회원 전용이며, 비회원 feed는 본문을 포함하지 않고 본문 검색도 하지 않습니다.

## 회원 활동 통계
회원 관리에서 글 작성, 댓글 작성(게시판+투표 의견), 투표 참여(투표별 응답 1회), 누적 받은 신고를 표시합니다. 신고는 처리 상태와 무관하며 위반 확정 수가 아닙니다. 숨김/소프트 삭제 기록도 집계하지만 영구 삭제되어 남지 않은 기록은 복원 집계할 수 없습니다. 체험 모드는 현재 브라우저에 남은 계정별 기록만 집계합니다. 서버 연결 시 010 다음 migration 011을 적용합니다. 집계는 운영자 RPC에서만 반환합니다.
홈은 상단 포스트와 흐르는 배너 다음 TOP 글 → 매거진 → 브랜드 소개 → 투표 순서입니다.
