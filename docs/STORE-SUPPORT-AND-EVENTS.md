# 상품·고객지원·이벤트 후속 개발

현재 상점 화면은 투표 탭으로 전환했습니다. 아래 상품 관리 내용은 이전 구현 기록이며, 현재 공개 탐색과 투표 기능은 `PUBLIC-BROWSING-AND-POLLS.md`를 확인하세요.

## 공개 테스트에서 확인할 수 있는 기능

로그인 `BBBB / 0000` → 스토어 → **상품 관리**에서 등록·편집·삭제·미리보기를 제공합니다. 상품명, 브랜드, 분류, 가격, 정상가, 재고, 추천 여부, 대표 이미지와 옵션별 이미지를 편집할 수 있습니다. 사진은 JPG·PNG·WebP, 원본 12MB 이하이며 브라우저에서 긴 변 1,600px 이하로 줄입니다. 상세 사진은 최대 6장입니다. 저장 공간이 부족하면 기존 상품과 작성 내용을 유지하며 실패를 표시합니다.

상품을 누르면 같은 팝업의 아래에 상세 설명과 사진을 표시합니다. 장바구니 버튼 다음, ‘한국에서 베트남으로 배송’ 이전의 **제품정보**는 기본적으로 접힌 상태입니다. 브랜드·원산지·원재료/성분·크기/용량/구성·사용/관리 안내를 클릭해서 확인합니다. 상품 삭제는 장바구니·찜에서도 반영하며 이전 테스트 주문의 상품명·옵션·금액은 보존합니다.

홈의 스토어 포스터 폭을 조금 줄이고 커뮤니티 포스터를 넓혔습니다. 작은 매거진 포스터는 제거했고 매거진 메뉴·기사 영역은 유지합니다. 하단 독과 PC 주 메뉴는 **홈 → 이벤트 → 커뮤니티 → 스토어 → 긴급** 다섯 개입니다. 마이페이지는 헤더·모바일 메뉴에서 열 수 있습니다.

로그인 `BBBB / 0000` → **이벤트** → **이벤트 등록**, 또는 카드 아래 **편집 / 삭제**에서 이벤트를 관리합니다. 제목·분류·소개·장소·일정(선택)·진행 상태·대표 이미지를 입력하고 카드 미리보기로 확인합니다. 진행 상태는 기획 중/모집 중/마감/종료이며 상태 표시는 실제 참가 접수를 활성화하지 않습니다. 대표 사진은 기존 사진 세 가지 중 선택하거나 상품 사진과 동일한 로컬 압축 처리로 업로드합니다. 사진 처리 실패나 저장 공간 부족 시 입력 내용과 기존 이벤트를 유지합니다.

`eventEdits`, `deletedEventIds`를 기존 저장 구조에 추가했습니다. 기본 이벤트도 수정·삭제할 수 있고 새로고침 후 다시 나타나지 않습니다. 편집은 같은 이벤트 ID와 기존 반응을 유지하며, 삭제는 확인창을 거쳐 해당 이벤트의 반응도 정리합니다. 기존 장바구니·상품·게시글·구매 기록은 유지합니다. 이벤트가 모두 없어도 등록 버튼과 빈 목록 안내를 제공합니다.

이벤트 관리는 현재 **같은 브라우저의 테스트 기능**입니다. 다른 방문자와 변경 내용을 공유하는 서버 저장이나 실제 관리자 인증은 제공하지 않습니다. 실제 소셜 회원에게는 로컬 관리 버튼을 표시하지 않습니다. 관리 화면은 한국어·베트남어·영어를 지원하며 언어 변경 중에도 작성 내용과 사진 선택을 유지합니다. 직접 작성한 이벤트 내용은 원문으로 표시합니다.

이벤트의 좋아요·싫어요는 동시에 선택할 수 없습니다. 같은 반응을 다시 누르면 취소되며 새로고침 후에도 유지됩니다. 공용 투표 수를 임의로 표시하지 않습니다.

## 고객지원 체험

상단 장바구니 옆 **고객지원** 아이콘 → 문의 작성 → 글 비밀번호(6자 이상) 설정 → 문의 등록 → 제목 선택 → 비밀번호 확인 순서로 테스트합니다. 커뮤니티와 달리 작성 아이디가 보이며 본인의 문의만 목록에 표시합니다. ‘운영자 화면 체험’에서는 이 브라우저의 전체 문의를 비밀번호 없이 열고 답변을 남길 수 있습니다. 아이디를 클릭하면 테스트 이용 시작일과 테스트 주문 상품을 확인합니다.

이것은 **브라우저 안의 체험**입니다. 실제 문의 접수, 안전한 운영자 인증 또는 다른 기기와의 공유를 제공하지 않습니다. 비밀번호 자체와 본문·답변·구매 스냅샷은 평문으로 저장하지 않지만, 같은 브라우저에 운영자 체험용 복호화 키도 보관하므로 실제 개인정보의 보안 경계로 사용할 수 없습니다. 목록용 제목·아이디·시각은 평문 메타데이터입니다. 실제 개인정보 입력을 금지하는 안내를 표시합니다.

실제 소셜 회원은 별도의 서버 어댑터를 사용합니다. 서버 연결 실패 시 브라우저 체험 데이터로 조용히 대체하거나 운영자 체험 버튼을 제공하지 않습니다.

## 실제 고객지원 연결에 필요한 설정

기존 소셜 인증 계획과 같은 Supabase를 사용하도록 코드를 준비했습니다. 프로젝트·키·소셜 제공자 설정이 없어 아직 활성화하지 않았고 SQL도 실제 서버에 적용하지 않았습니다.

1. 선택한 Supabase 프로젝트에 기존 `001`·`002`와 새 `003`·`004`·`005` 마이그레이션을 순서대로 검토·적용합니다. 이미 적용한 마이그레이션은 다시 실행하지 않습니다.
2. `docs/SOCIAL-SIGNUP.md`에 따라 구글·페이스북 OAuth를 연결하고 빌드 환경에 공개 URL/anon key를 설정합니다. 서비스 역할 키는 클라이언트에 넣지 않습니다.
3. 실제 운영자가 가입한 후 서버의 `user_roles`에 그 회원 UUID의 `admin` 역할을 소유자 권한으로 부여합니다. 브라우저나 프로필 수정으로 역할을 부여하지 않습니다.
4. 일반 회원 두 명과 운영자 한 명으로 서버 권한을 검증합니다. 다른 회원은 문의 목록·본문을 볼 수 없고, 본인도 글 비밀번호가 맞아야 본문을 봅니다. 운영자는 비밀번호 없이 열고 답변합니다. 타 회원의 가입일·구매 내역은 운영자만 조회합니다.

`004`는 문의·답변·암호 시도 테이블에 RLS를 켜고 직접 읽기/쓰기 권한을 주지 않습니다. 비밀번호는 서버에서 bcrypt로 해시하며, 지정한 RPC만 계정·역할·비밀번호를 확인한 뒤 본문을 반환합니다. 5회 실패하면 10분 동안 잠기며 실패 횟수가 롤백되지 않도록 오류 결과를 반환합니다. 구매 정보에는 결제된 주문과 상품·수량·금액만 포함하며 주소·결제 참조·이메일은 반환하지 않습니다. 문의는 시간당 10건으로 제한합니다.

## 신고 1회 제한과 50건 임시 숨김

같은 이용자가 같은 **게시글**을 다시 신고할 수 없습니다. 기각·숨김·복원·새로고침 후에도 제한을 유지합니다. 댓글은 각 댓글별 1회이며 게시글 신고 수에는 합산하지 않습니다. 서로 다른 신고자 49명까지는 노출하고 50번째 신고에서 글을 우선 숨깁니다. 운영자 검토 대기 상태를 유지하며 신고함에서 고유 신고자 수와 임시 숨김 상태를 확인합니다.

운영자가 숨김을 확정하거나 기각·복원할 수 있습니다. 기존 신고와 누적 수는 삭제하지 않습니다. 운영자가 검토 후 복원한 글을 51번째 신고 하나로 즉시 다시 숨기지는 않습니다.

공개 테스트는 기기별 키로 제한·집계합니다. 실제 회원 여러 명의 신고는 서버 연결 전에는 모이지 않습니다. `005`는 실제 서버에서 회원/게시글 고유 인덱스로 중복을 차단하며, 원자적인 DB 카운터가 50에 도달하면 상태를 숨김으로 전환합니다. 클라이언트가 보낸 신고자 ID·누적 숫자·운영자 플래그를 신뢰하지 않습니다.

## 검증 범위

등록·편집·삭제·재복원, 주문 스냅샷 보존, 재고/옵션 변경, 제품정보 접힘 위치, 독 이동, 이벤트 등록·편집·삭제와 빈 목록·기존 반응·이전 저장 데이터 유지·3개 언어 전환, 문의 비밀번호·소유자 구분·운영자 답변·회원 정보, 중복 신고와 49/50건 경계를 DOM/데이터 자동 테스트로 확인합니다. TypeScript와 정적 프로덕션 빌드를 실행합니다.

브라우저 조작 도구가 없어 실제 화면 크기별 시각·터치·사진 업로드 QA는 직접 실행하지 못했습니다. Supabase SQL은 실제 프로젝트에서 실행·권한 테스트하기 전의 준비 코드입니다. 이 검증 범위를 실제 서버 보안 검증과 혼동하지 않습니다.
