# 공개 탐색과 사진 투표

## 현재 화면

홈(`/`)은 비회원에게 바로 열립니다. 주 메뉴와 모바일 독은 홈 → 이벤트 → 커뮤니티 → 투표 → 긴급 순서입니다. 상점·장바구니·상품 관리 버튼은 현재 화면에서 제외했고, 기존 상품 컴포넌트·데이터 처리 코드와 저장 데이터는 보존했습니다. 이전 `#shop`, `#catalog`, `#favorites` 링크는 `#polls`로 연결됩니다. 상점의 마지막 전체 화면 코드는 Git 커밋 `338fd8fb1ff9f7d731fd69d0cbfb62cfa3b8c627`에서 확인할 수 있습니다.

비회원은 홈과 목록의 사진·이름·게시글 제목을 둘러볼 수 있습니다. 글/매거진 본문 읽기, 글쓰기, 이벤트 진입/읽기, 투표 상세 열기와 참여, 의견 작성, 고객지원·내 활동·관리 화면은 로그인을 요구합니다. 이벤트 목록은 로그인 팝업을 닫으면 사진과 제목의 미리보기만 보여줍니다. 긴급 소개는 공개하되 요청 작성은 로그인 후 열립니다. 개인정보·이용약관 문서는 비회원도 읽을 수 있습니다.

상단 우측에 로그인/회원가입을 텍스트로 배치했습니다. 로그인은 로고와 현지화된 `K-문화 · 플레이 · 커뮤니티` 문구가 있는 팝업입니다. 팝업 아래 회원가입 링크가 있으며, 로그인 후에는 클릭했던 글·투표·작성 화면으로 이어집니다. 취소하면 요청한 동작을 실행하지 않습니다. 로그아웃하면 상세 화면·작성 상태·긴급 요청의 탭 메모리를 닫고 비회원 홈으로 돌아갑니다. 회원가입 페이지의 로그인 링크는 `/?login=1`로 이 팝업을 엽니다.

## 운영자 작성과 상세페이지

현재 운영자 체험 계정은 `BBBB / 0000`입니다. 투표 탭의 ‘투표글 등록’과 사진 위 편집/삭제 아이콘을 사용합니다. 일반 회원에게 이 관리 버튼을 표시하지 않습니다. 실제 소셜 회원의 운영자 역할은 Supabase의 `anonymous_access` RPC에서 DB 관리자 역할을 확인하며, 아이디 이름이 BBBB라는 이유로 운영 권한을 부여하지 않습니다.

작성 항목:

- 투표 이름, 한 줄 소개, 대표 사진
- 상세페이지의 제목·본문·사진 블록. 추가/삭제/위아래 순서 변경과 상세 미리보기를 제공
- 최대 12개 상세 블록, 그중 사진 최대 6개
- 투표 질문 1~3개, 질문별 선택지 2~5개. 모든 질문과 선택지는 운영자가 직접 작성

카드는 사진과 이름만 표시합니다. 클릭하면 큰 대표 사진, 소개, 상세 블록, 투표 항목, 익명 의견을 넓은 팝업으로 표시합니다. 팝업 X는 스크롤 영역 밖에 유지됩니다. 사진은 JPG/PNG/WebP, 원본 12MB 이하를 브라우저에서 압축하며 업로드 실패나 저장 용량 부족 시 편집 초안을 유지합니다.

첫 참여 전에는 질문·선택지를 수정할 수 있습니다. 참여자가 생기면 질문과 선택지는 고정하고, 사진·제목·소개·상세 블록은 계속 편집할 수 있습니다. 기존 표의 의미와 집계를 보존하기 위한 동작입니다. 삭제는 확인창을 거치며 해당 투표의 참여 결과와 댓글도 제거합니다.

## 참여와 익명성

각 질문은 단일 선택 라디오입니다. 모든 질문에 하나씩 답해야 ‘참여’가 활성화됩니다. 선택 전체를 한 번에 검증하고 하나의 투표 응답으로 저장합니다. 누락 질문, 모르는 선택지, 한 질문에 배열/복수 선택, 추가 질문 키, 중복 참여, 오래된 버전의 투표를 거부합니다.

참여 후 같은 위치의 보기를 질문별 표수·비율로 교체합니다. 본인의 선택만 체크로 표시하며 다른 참여자의 신원은 노출하지 않습니다. 재방문 시 참여 완료 상태와 집계를 복원합니다. 아직 참여하지 않은 회원은 집계를 볼 수 없습니다.

투표 참여자만 익명 댓글을 작성할 수 있습니다. 운영자 댓글도 같은 ‘익명’으로 표시하며 작성자/회원 ID·아바타·프로필·팔로우·DM을 제공하지 않습니다. 댓글은 원문을 유지하고 UI 언어 변경으로 내용을 바꾸지 않습니다.

## 현재 저장 방식과 실제 운영 연결

Supabase URL/공개 키가 제공되지 않은 공개 테스트에서는 브라우저 저장을 사용합니다. 기존 `ggo-experience-v1` 저장 키와 schema 2에 `pollEdits`, `deletedPollIds`, `pollBallots`, `pollComments`를 추가했습니다. 이전 상품·장바구니·글·이벤트 데이터는 유지합니다. 손상되거나 중복된 투표 응답을 복원할 때 제거하고, 유효한 참여가 없는 댓글은 복원하지 않습니다.

이 브라우저 체험은 다른 방문자와 집계를 공유하는 서버 보안 경계가 아닙니다. 실제 소셜 회원은 Supabase 어댑터를 사용하고, 서버 연결이 안 되면 로컬 관리자 체험/투표로 자동 대체하지 않습니다. 서버가 연결되면 `poll_summaries`는 비회원에게 사진·이름만 반환하며, 상세·참여·댓글·운영자 관리는 인증된 RPC로 처리합니다.

`supabase/migrations/202611160007_polls.sql`은 기존 001–006 이후 적용할 준비 코드입니다. 이번 작업에서 실제 DB에는 적용하지 않았습니다.

- 회원/투표 복합 기본키로 1인 1회 참여를 DB에서 제한
- 서버가 로그인 UID·운영자 역할·질문 버전·선택지·전체 응답을 검증
- 투표 행 잠금과 단일 트랜잭션으로 동시에 들어온 참여/편집을 처리
- 참여 기록에 대한 외래키와 RPC 검증으로 참여자만 댓글 작성
- 집계는 참여 완료한 회원에게만 반환하고 댓글에는 작성자 ID를 반환하지 않음
- 테이블 직접 접근은 RLS와 권한 회수로 제한. 서버의 `public.is_admin()`만 운영자 편집/삭제를 허용
- 운영자만 `poll-media` 사진 업로드 가능
- 기존 익명 게시판도 비회원에게는 목록용 컬럼만 허용하고 본문/댓글 읽기 권한은 회원으로 제한

운영 연결에는 소유자 Supabase 프로젝트·OAuth 설정·실제 역할 부여가 필요합니다. 기존 브라우저 초안을 운영 DB에 자동 업로드하지 않습니다. 실제 DB에서 일반 회원 두 명·운영자·비로그인 상태로 RPC/RLS와 동시 참여를 검증한 뒤 운영 전환해야 합니다. 로그인 키와 OAuth 활성화는 별도 출시 연결 작업으로 남아 있습니다.

## 검증

DOM/데이터 테스트로 공개 홈, 로그인 팝업과 이어보기/취소/로그아웃, 모든 진입점의 로그인 요구, 운영자 권한, 상세 블록 구성/미리보기, 질문·선택지 상한, 단일/전체 선택, 중복 참여, 참여 후 집계·댓글, 저장/재방문, 세 언어와 입력 상태 유지를 확인합니다. PostgreSQL 및 PL/pgSQL 구문은 별도 파서로 확인합니다. 이는 실제 Supabase DB의 실행·권한 검증을 대신하지 않습니다.

현재 환경에는 브라우저 화면 도구가 없어 실제 모바일/PC 시각 검수와 사진 압축의 실브라우저 QA는 수행하지 못했습니다. 정적 빌드·타입 검사·자동 테스트·배포 파일 HTTP 검증을 수행합니다.
